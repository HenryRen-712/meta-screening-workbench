# 技术规范

## 当前技术栈

- 前端：React + TypeScript + Vite。
- 样式：原生 CSS。
- 图标：lucide-react。
- 数据保存：IndexedDB 优先，localStorage 仅作小项目兼容和元信息。
- PDF 附件：独立 IndexedDB 对象仓保存，项目 JSON 仅保存附件元数据。
- PDF 文字提取：`pdfjs-dist` 在浏览器本机逐页读取文字层；不上传 PDF，不依赖在线 API。
- 项目备份：JSON 文件。
- 在线发布：GitHub Pages。

## 后续 v2 技术方向

- 云端协作：Supabase Auth + Postgres + Row Level Security。
- 云端函数：Supabase Edge Functions，用于 AI 调用和需要服务端 Key 的任务。
- 前端公开变量：只允许 `VITE_SUPABASE_URL`、`VITE_SUPABASE_ANON_KEY`。
- 私密变量：Supabase service role key、AI API key 只能放服务端，不能进入前端代码或公开仓库。

## 开发原则

- 每次只做一个小目标。
- 优先复用现有结构。
- 不为未实施功能提前引入依赖。
- 数据结构变更必须同时提供兼容旧项目备份的恢复逻辑。
- 旧备份中没有最终 Meta 纳入确认字段时，迁移逻辑只新增空的 A/B 确认容器，不能把原全文“纳入”自动写成最终 Meta 纳入。
- 涉及保存、导入、导出、筛选决定的改动必须谨慎，必须构建和手动验证。

## 文件职责

- `src/main.tsx`：当前应用主逻辑、数据结构、导入导出、页面组件。
- `src/styles.css`：全局样式和响应式布局。
- `index.html`：页面入口。
- `README.md`：用户启动和使用说明。
- `docs/`：开发标准、需求、技术、设计、流程和测试文档。
- `开发日志/`：每日开发记录。
- `测试报告/`：压力测试和专项测试记录。

## 数据安全

- 默认不上传用户题录、PDF、筛选记录和备份 JSON。
- PDF 上传后只能保存到当前浏览器本机；不得将 PDF 二进制写进公开仓库、localStorage 或项目 JSON 备份。
- PDF 自动匹配必须优先使用 DOI、PMID；题名匹配仅接受完整题名文件名，匹配不到时保留为未匹配，避免误关联。
- 自动提取结果必须包含证据片段、页码、PDF SHA-256、提取状态和警告；规则只能复制原文候选，不做语义补写或未经证实的数值换算。
- 自动提取值只填充空白字段或替换上一版自动值，人工已修改内容不得覆盖。规则收紧或更换 PDF 后，失去证据支持的旧自动值必须清除。
- PDF 全文文字不得写入项目 JSON；只保存有限证据片段，控制项目体积和隐私暴露。
- 正式筛选必须定期导出 JSON 备份。
- 不在代码中写入 API Key、账号密码、真实研究隐私数据。
- 恢复项目 JSON 时必须校验基础字段。
- 云端功能上线前，不能移除本地备份和恢复能力。

## 导入解析原则

- 优先支持 RIS、BibTeX、CSV。
- CSV 必须处理中文表头和常见英文表头。
- DOI、PMID、标题是去重优先字段。
- 导入大文件时必须分块让出浏览器主线程，避免页面假死。

## 导出原则

- CSV 必须带 UTF-8 BOM，避免 Excel 打开中文乱码。
- Word 草稿可以使用 `.doc` HTML 格式，但必须能被 Word/WPS 打开。
- 导出统计只能来自当前项目状态，不能生成虚构数字。

## 依赖管理

- 新依赖必须有明确用途。
- 引入前必须记录在开发日志中。
- 引入后必须构建通过。
- 暂未使用的依赖不得保留。
